# Domain docs

This repo uses a single-context layout:
- GLOSSARY.md at the repository root
- docs/adr/ for architectural decisions

## Before exploring

Read the glossary and ADRs relevant to the area being explored.

If these documents are absent, proceed silently. Create them lazily
through domain-modeling when terminology or decisions are resolved.

## Vocabulary and decisions

Use the glossary's established terms in issues, code, tests, and proposals.
Note missing concepts for domain-modeling.

Surface conflicts with existing ADRs explicitly, including the reason
for proposing a different direction.
